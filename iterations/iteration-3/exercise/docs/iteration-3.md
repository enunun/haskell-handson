# Iteration 3：費目ごとの集計(演習)

## このIterationで作るもの

明細と合計のあいだに，費目ごとの小計を表示する．

```console
$ cabal run kakeibo-iteration3 -- 食費:1200 交通費:350 食費:350
食費 1,200円
交通費 350円
食費 350円
費目別:
  食費 1,550円
  交通費 350円
合計: 1,900円
```

あわせて，`total`を`foldr`で書き直す．
作りながら，関数を引数に取る関数(高階関数)の使い方を学ぶ．

## 進め方

演習3-1から順に進める．
詰まったら，`../solution/docs/iteration-3.md`の同じ番号の節を読む．
コマンドはすべてリポジトリ直下で実行する．

## 演習3-1：パッケージを登録してビルドする

1. `cabal.project`の`packages`に，このパッケージのディレクトリを追記する．
2. このパッケージのテストをすべて実行し，引き継いだテストがすべて通ることを確かめる．
3. このパッケージの実行ファイルを，引数`食費:1200 交通費:350 食費:350`で実行し，今の表示を確かめる．

## 演習3-2：高階関数を試す

[Iteration 3で使う文法・概念](../../../../docs/haskell/iteration-3.md)を読み，GHCiで例を試す．
読み終えたら，このパッケージを読み込んだGHCiで次を試す．
`Entry`を使うので，最初に`import Kakeibo.Entry`と入力する．

1. `es = [Entry Food 1200, Entry Transport 350, Entry Food 350]`と定義する．
2. `es`から食費の支出だけを取り出す式を，ラムダ式を使って書く．次に，セクションと関数合成(`(== Food) . category`)を使って書き直す．
3. `es`の金額のリストを`map`で作り，その合計を`foldr`で求める．
4. `[minBound .. maxBound] :: [Category]`を評価する．`Category`の定義に`deriving (Enum, Bounded)`がないため，エラーになる．エラーメッセージを読む．

## 演習3-3：テストリストを書く

次の要求を読み，[TESTLIST.md](../TESTLIST.md)にテストリストを書く．

### 要求

- 明細の後ろに`費目別:`という行を表示し，続けて費目ごとの小計を1行ずつ表示する．小計の行は，行頭に空白を2つ入れて`  費目 金額`の形にする．
- 小計は，費目の定義の順(食費・交通費・日用品・その他)に並べる．
- 支出が1件もない費目の小計は表示しない．
- 最後の`合計: 〜円`の行は，これまでどおり表示する．
- `total`を，`foldr`を使って定義し直す．振る舞いは変えない．

### 使い方の例

```console
$ kakeibo 食費:1200 交通費:350 食費:350
食費 1,200円
交通費 350円
食費 350円
費目別:
  食費 1,550円
  交通費 350円
合計: 1,900円
$ kakeibo 800 日用品:500
その他 800円
日用品 500円
費目別:
  日用品 500円
  その他 800円
合計: 1,300円
```

### 作るもの

新しいモジュール`Kakeibo.Summary`を作る．

| モジュール | 関数 | 役割 |
|---|---|---|
| `Kakeibo.Summary` | `summarize :: [Entry] -> [(Category, Int)]` | 費目ごとの小計を，費目の定義順に並べて返す．支出がない費目は含めない． |
| `Kakeibo.App` | `run :: [String] -> [String]` | 費目別の小計を表示するように変える．型は変えない． |

`Category`の`deriving`に`Enum`と`Bounded`を足してよい．

### 考えること

- `summarize`の結果は，費目と小計の組のリストである．どんな入力を与えると，「足し合わせる」「並べる」「含めない」のそれぞれを確かめられるか．
- 小計の行の形(字下げ，`費目別:`の見出し)は，どのテストで確かめるか．
- 既存の結合テストのうち，期待値が変わるものはどれか．

## 演習3-4：テスト駆動で実装する

テストリストの項目を1つずつRed→Greenにする．

### モジュールを作る

- `src/Kakeibo/Summary.hs`を作り，`library`の`exposed-modules`に追記する．
- `test/unit/Kakeibo/SummarySpec.hs`を作り，`test-suite unit`の`other-modules`に追記する．
- 最初は`summarize`の型シグネチャと`error "TODO"`だけを書き，テストがRedになることを確かめる．

### `summarize`のヒント

- ある費目の支出だけを取り出すには`filter`を使う．条件は，最初はラムダ式で書くとわかりやすい．
- 取り出した支出の金額のリストは`map amount`で作れる．合計は`total`で求める．
- すべての費目のリストは`[minBound .. maxBound]`で作れる．そのために`Category`の`deriving`に`Enum`と`Bounded`を足す．
- 「支出がない費目を含めない」は，費目のリストを`filter`で絞ってから小計を作ると書ける．リストが空かどうかは`null`で調べる．
- `where`で，「ある費目の支出のリスト」を返す関数に名前を付けると，同じ式を2回書かずに済む．
- テストで`Entry`の値を並べるときは，`Entry Food 1200`のようにフィールド名を省いて書くと短くなる．

### `run`のヒント

- `summarize`の結果の各要素(タプル)を1行にする関数を`where`などで定義し，`map`で適用する．タプルはパターン`(c, subtotal)`で分解できる．
- 明細の行，`費目別:`の行，小計の行，合計の行を`++`でつなげる．

### `total`の書き直し

- 書き直す前後で，`total`のテストがすべて通ることを確かめる．
- `foldr`の1つ目の引数には，`+`を関数として渡す(`(+)`)．

### 整える

テストがすべて通ったら，`summarize`の中のラムダ式を，セクションと関数合成で書き直せないか試す．
書き直したら，もう一度テストを実行する．

## 演習3-6(発展)：費目ごとの件数を表示する

小計の後ろに，その費目の支出の件数を表示する．

```console

…
費目別:
  食費 1,550円(2件)
  交通費 350円(1件)
合計: 1,900円
```

1. `summarize`の結果の型をどう変えるかを決め，テストリストに項目を足す．既存のテストのうち，型の変更で書き換えが必要になるものも探す．
2. 1項目ずつRed→Greenを回す．
