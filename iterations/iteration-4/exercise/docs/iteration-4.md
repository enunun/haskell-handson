# Iteration 4：入力の誤りを知らせる(演習)

## このIterationで作るもの

これまでの`kakeibo`は，金額として読めない引数を渡されると`Prelude.read: no parse`で止まっていた．
このIterationでは，誤った引数を渡されたら，どの引数がなぜ誤っているかを標準エラー出力に表示し，終了コード1で終わるようにする．

```console
$ cabal run -v0 kakeibo-iteration4 -- 食費:1200 交通費:abc
金額は正の整数で書いてください: 交通費:abc
$ echo $?
1
```

作りながら，失敗を値として表す`Maybe`と`Either`を学ぶ．

## 進め方

演習4-1から順に進める．
詰まったら，`../solution/docs/iteration-4.md`の同じ番号の節を読む．
コマンドはすべてリポジトリ直下で実行する．

## 演習4-1：パッケージを登録してビルドする

1. `cabal.project`の`packages`に，このパッケージのディレクトリを追記する．
2. このパッケージのテストをすべて実行し，引き継いだテストがすべて通ることを確かめる．
3. このパッケージの実行ファイルを，引数`食費:1200 交通費:abc`で実行する．表示と終了コード(`echo $?`)を確かめる．cabal自身のメッセージを消すには，`cabal run`に`-v0`を付ける．
4. 引数`食費:0`と`食費:-500`でも実行し，どう表示されるかを確かめる．

## 演習4-2：`Maybe`と`Either`を試す

[Iteration 4で使う文法・概念](../../../../docs/haskell/iteration-4.md)を読み，GHCiで例を試す．
読み終えたら，GHCiで次を試す．

1. `import Text.Read (readMaybe)`と入力し，`readMaybe "1200" :: Maybe Int`，`readMaybe "abc" :: Maybe Int`，`readMaybe "-5" :: Maybe Int`を評価する．
2. `read "abc" :: Int`を評価し，1.の`readMaybe "abc" :: Maybe Int`と結果を比べる．`read`が部分関数で，`readMaybe`が全域関数である理由を，型シグネチャ(`:t read`，`:t readMaybe`)を見ながら説明する．
3. 文字列を読み，正の整数なら`Just`で，そうでなければ`Nothing`を返す関数を定義する．
4. 3.の関数を使って，`Either String Int`を返す関数を定義する．`Left`には，読めなかった文字列を含むメッセージを入れる．

## 演習4-3：テストリストを書く

次の要求を読み，[TESTLIST.md](../TESTLIST.md)にテストリストを書く．

### 要求

- 金額は正の整数(1以上の整数)でなければならない．数として読めない文字列，小数，0，負の数は誤りである．
- 誤った引数があれば，`金額は正の整数で書いてください: 引数`というエラーメッセージを標準エラー出力に表示し，終了コード1で終わる．`引数`には，誤った引数をそのまま入れる．
- 誤った引数が複数あれば，最初のものについてのエラーメッセージを表示する．
- 誤った引数があれば，明細や合計は表示しない．
- 引数がすべて正しいときの表示は，これまでと変えない．

### 使い方の例

```console
$ kakeibo 食費:1200 交通費:abc
金額は正の整数で書いてください: 交通費:abc
$ kakeibo 食費:0 交通費:abc
金額は正の整数で書いてください: 食費:0
$ kakeibo 1.5
金額は正の整数で書いてください: 1.5
```

### 作るもの

エラーを値として返すように，関数の型を変える．

| モジュール | 関数 | 役割 |
|---|---|---|
| `Kakeibo.Entry` | `parseAmount :: String -> Maybe Int` | 金額を読み取る．正の整数でなければ`Nothing`を返す．(新規) |
| `Kakeibo.Entry` | `parseEntry :: String -> Either String Entry` | `費目:金額`を読み取る．金額が誤っていればエラーメッセージを返す．(型を変更) |
| `Kakeibo.Entry` | `parseEntries :: [String] -> Either String [Entry]` | 引数をすべて読み取る．誤った引数があれば，最初のもののエラーメッセージを返す．(新規) |
| `Kakeibo.App` | `run :: [String] -> Either String [String]` | 誤った引数があればエラーメッセージを返す．(型を変更) |

`app/Main.hs`の`main`も，`run`が`Left`を返したら標準エラー出力に表示して終了コード1で終わるように変える．

### 考えること

- 「正の整数でない」には，どんな種類の文字列があるか．それぞれを`parseAmount`の単体テストで確かめるか．
- `parseEntry`の型が変わると，既存のテストはどう書き換わるか．
- 標準エラー出力と終了コードは，`main`(`IO`)の中の処理である．このIterationのテストでは，どこまでを自動のテストで確かめ，どこからを手で確かめるか．

## 演習4-4：テスト駆動で実装する

型を変えると，その関数を使っている場所がすべてコンパイルできなくなる．
次の順に進めると，コンパイルが通る状態を保ちながら1項目ずつ進められる．

### `parseAmount`

新しい関数なので，これまでと同じようにテストを1つずつ足して進める．

- `readMaybe`は`Text.Read`モジュールにある．
- `readMaybe`の結果を`case`で分け，`Just`の場合にガードで正かどうかを調べる．

### `parseEntry`

1. `parseEntry`の既存のテストの期待値を`Right (…)`に変え，誤った金額のテストを足す．
2. `parseEntry`の型を`String -> Either String Entry`に変える．
3. ライブラリのコンパイルが`Kakeibo.App`で失敗する．`run`の定義を，いったん型はそのままで`run _ = error "TODO"`だけにする．こうすると，ライブラリがコンパイルでき，単体テストを進められる(結合テストは`run`を直すまで失敗する)．
4. 単体テストを実行してRedを確かめ，`parseEntry`を実装する．`parseAmount`の結果を`case`で分け，`Nothing`なら`Left`，`Just`なら`Right`を返す．

### `parseEntries`

- 空のリスト，すべて正しい場合，誤った引数がある場合，誤った引数が複数ある場合を，1つずつRed→Greenにする．
- 先頭の要素を`parseEntry`で読み，`Left`ならそのまま返し，`Right`なら残りを再帰で読む．残りの結果にも`Left`と`Right`がある．

### `run`と`main`

1. 結合テストの期待値を`Right [ … ]`に変え，誤った引数のテストを足す．
2. `run`の型を`[String] -> Either String [String]`に変え，実装する．明細・小計・合計の行を作る部分は，`[Entry] -> [String]`の関数に分けると読みやすい．
3. 実行ファイルのコンパイルが`app/Main.hs`で失敗する．`main`を，`run`の結果を`case`で分けるように変える．
4. テストがすべて通ったら，演習4-1と同じ引数で実行し，表示と終了コードを確かめる．

## 演習4-5：振り返る

1. 自分の`TESTLIST.md`と，解答例の[TESTLIST.md](../../solution/TESTLIST.md)を比べる．
2. `parseEntry`を`Maybe Entry`を返す関数にしていたら，`run`はどんなエラーメッセージを表示できたか．`Either`にしたことで何ができるようになったか．
3. 標準エラー出力への表示と終了コードを手で確かめた．この部分に誤りがあっても，自動のテストは失敗しない．`main`の中の処理を少なく保つことには，どんな意味があるか．
4. `parseEntries`の`case`の入れ子で，同じ形が繰り返し出てくるのはどこか．

## 演習4-6(発展)：誤りの理由を分ける

エラーメッセージを，誤りの種類によって分ける．

```console
$ kakeibo 食費:abc
金額は整数で書いてください: 食費:abc
$ kakeibo 食費:0
金額は1円以上にしてください: 食費:0
```

1. `parseAmount`の型を，理由を返せる型に変えることから考える．
2. テストリストを更新し，1項目ずつRed→Greenを回す．
