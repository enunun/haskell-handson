# Iteration 1：3桁区切りと，支出がないときの表示(演習)

## このIterationで作るもの

Iteration 0で作った`kakeibo`の表示を改める．
金額を3桁ごとにカンマで区切り，引数がないときは合計の代わりに支出がないことを表示する．

```console
$ cabal run kakeibo-iteration1 -- 1200 350 800
合計: 2,350円
$ cabal run kakeibo-iteration1
支出はありません
```

あわせて，`total`を`sum`に頼らない再帰の定義に書き直す．
作りながら，パターンマッチ・再帰・ガード・`where`を学ぶ．

## 進め方

演習1-1から順に進める．
詰まったら，`../solution/docs/iteration-1.md`の同じ番号の節を読む．
コマンドはすべてリポジトリ直下で実行する．

## 演習1-1：パッケージを登録してビルドする

1. `cabal.project`の`packages`に，このパッケージのディレクトリ(`iterations/iteration-1/exercise`)を追記する．
2. このパッケージ(`kakeibo-iteration1`)のテストをすべて実行し，Iteration 0から引き継いだテストがすべて通ることを確かめる．
3. このパッケージの実行ファイルを，引数`1234567`で実行する．次に引数なしで実行する．今の表示を確かめておく．

コマンドの形を忘れたら，[cabal](../../../../docs/cabal.md)の「コマンド」を見る．

## 演習1-2：パターンマッチと再帰を試す

[Iteration 1で使う文法・概念](../../../../docs/haskell/iteration-1.md)を読み，GHCiで例を試す．
読み終えたら，GHCiで次を試す．GHCiは`cabal repl`にこのパッケージ名を渡して起動する．

1. `take 1 "1234"`，`drop 1 "1234"`，`length "1234"`を評価する．
2. リストの要素の数を数える関数`count :: [Int] -> Int`を，パターンマッチと再帰で定義する(`:{`と`:}`を使う)．`count []`と`count [7, 8, 9]`を評価する．
3. `count`の定義から`[]`の場合を消して定義し直すと，`count [7, 8, 9]`はどうなるか．予想してから試す．
4. 金額が1000以上なら`"高額"`，それ以外なら`"少額"`を返す関数を，ガードを使って定義する．

## 演習1-3：テストリストを書く

次の要求を読み，[TESTLIST.md](../TESTLIST.md)にテストリストを書く．

### 要求

- 金額を表示するときは，右から3桁ごとにカンマで区切る．
- 引数がないときは，`支出はありません`と表示する．
- `total`を，`sum`を使わずにパターンマッチと再帰で定義し直す．振る舞いは変えない．

### 使い方の例

```console
$ kakeibo 1200 350 800
合計: 2,350円
$ kakeibo 1234567
合計: 1,234,567円
$ kakeibo
支出はありません
```

### 作るもの

関数の型は変えない．
`formatYen`の中で使う補助の関数は，自由に作ってよい．

| モジュール | 関数 | このIterationで変えること |
|---|---|---|
| `Kakeibo.Money` | `total :: [Int] -> Int` | 再帰で定義し直す． |
| `Kakeibo.Money` | `formatYen :: Int -> String` | 3桁ごとにカンマを入れる． |
| `Kakeibo.App` | `run :: [String] -> [String]` | 引数がないときの表示を変える． |

### 考えること

- 既存のテストのうち，期待値が変わるものはどれか．単体テストと結合テストの両方を読む．
- 3桁区切りを確かめるには，何桁の金額を試せばよいか．カンマが入るか入らないかの境目，カンマが1つか2つかの境目はどこか．
- `total`の書き直しのために，新しいテストは必要か．

## 演習1-4：設計書を更新する

`design/`の設計書は，Iteration 0の解答例の設計書から始まる．
演習1-3で書いたテストリストの振る舞いを実現するために，どこを変えるかを決めて設計書を更新する．
書き方は[設計書の書き方](../../../../docs/design.md)を参照する．

- Context・Container・Componentの図のうち，説明の文を変えるものはあるか．モジュールの構成は変わるか．
- `04-code.md`の型と関数の流れに，引数が空のときの流れを足す．
- `formatYen`の中で3桁区切りを作る流れを，別の図として描く．`formatYen`の中だけで使う補助の関数も，名前と型を決めて描き，関数の表に「公開しない」関数として足す．
- 図だけでは伝わらない規則(3桁区切りの規則など)は，図の下に箇条書きで書く．

更新したら，`mise run lint`で図の構文を確かめる．

## 演習1-5：テスト駆動で実装する

テストリストの項目を1つずつRed→Greenにする．
既存のテストの期待値を変える項目も，期待値を変えて失敗を確かめてから実装する．

### 3桁区切り

- `show`で数字の並び(`String`)にしてから，カンマを入れる．
- 右から3桁は`drop (length digits - 3) digits`，残りは`take (length digits - 3) digits`で取り出せる．
- 残りの部分にもカンマを入れる必要がある．残りの部分は元より3桁短いので，同じ関数で再帰的に処理できる．どの長さになったら再帰をやめるかを，ガードで書く．
- 補助の関数をエクスポートしなければ，テストは`formatYen`を通して書く．
- `formatYen`を変えると，`run`の結合テストの期待値にも影響する．単体テストを通したら，パッケージのテストをすべて実行して確かめる．

### 支出がないときの表示

- `run`の定義を，空のリストの場合と，それ以外の場合に分ける．
- 定義を書く順番に気を付ける．

### `total`の書き直し

- 書き直す前に単体テストを実行し，すべて通ることを確かめる．
- 空のリストの場合と，先頭の要素と残りのリストに分けられる場合で定義する．
- 書き直したら，もう一度テストを実行する．

## 演習1-6：振り返る

1. 自分の`TESTLIST.md`と，解答例の[TESTLIST.md](../../solution/TESTLIST.md)を比べる．
2. `run`の2つの定義の順番を入れ替えるとどうなるか．コンパイル時の警告と，テストの結果を確かめる．
3. `total`の書き直しで，誤りがないことを保証したのはどのテストか．書き直しの前後でテストの結果を見比べたことには，どんな意味があったか．
4. 3桁区切りの細かい場合分けを，単体テストと結合テストのどちらで確かめたか．それはなぜか．
5. 設計書と実装を見比べる．実装してみて，設計書と違う形になったところはあるか．あれば，設計書を実装に合わせて直す．
