# Iteration 0：式・型・関数・モジュール

Iteration 0で使う文法と概念をまとめる．
例はGHCi(対話環境)で試せる．`cabal repl <パッケージ名>`で起動し，`ghci>`のあとに式を入力する．

## GHCi

GHCiは，Haskellの式をその場で評価する対話環境である．

```console
$ cabal repl kakeibo-iteration0
ghci> 1 + 2
3
ghci> :t 'a'
'a' :: Char
ghci> :q
```

よく使うコマンドは次のとおり．

| コマンド | 意味 |
|---|---|
| `:t 式` | 式の型を表示する． |
| `:i 名前` | 関数・型・型クラスの情報を表示する． |
| `:r` | ファイルを読み込み直す．ソースを編集したら実行する． |
| `:q` | GHCiを終了する． |

`cabal repl`でパッケージを読み込むと，そのパッケージのモジュールの関数を呼べる．
別のモジュールを使うには`import Kakeibo.Money`のように入力する．

### GHCiでの日本語の表示

GHCiは，評価した値を`show`で文字列にして表示する．
`show`は，文字列の中の日本語などの文字を`\20870`のような番号に置き換える．
そのため，日本語を含む文字列を評価すると，番号の並びで表示される．

```console
ghci> "1200" ++ "円"
"1200\20870"
ghci> putStrLn ("1200" ++ "円")
1200円
```

`putStrLn`は，文字列をそのまま表示する．
日本語の中身を確かめたいときは`putStrLn`を使う．
hspecのテストの失敗メッセージでは，日本語はそのまま表示される．

## 式・値・型

Haskellのプログラムは式でできている．
式を評価すると値になり，どの式にも型がある．

```console
ghci> :t True
True :: Bool
ghci> :t "食費"
"食費" :: String
ghci> :t 1200 :: Int
1200 :: Int :: Int
```

`::`は「左の式は右の型を持つ」という意味である．
Iteration 0で使う型は次のとおり．

| 型 | 値の例 | 意味 |
|---|---|---|
| `Int` | `1200`，`-5` | 固定長の整数(64ビットの環境では64ビット)． |
| `Bool` | `True`，`False` | 真偽値． |
| `Char` | `'a'`，`'円'` | 1文字．シングルクォートで囲む． |
| `String` | `"1200円"` | 文字列．ダブルクォートで囲む．中身は`Char`のリスト(`[Char]`)である． |
| `[Int]` | `[1200, 350]`，`[]` | `Int`のリスト．要素の型はすべて同じでなければならない． |

整数のリテラル`1200`は，`Int`だけでなくほかの数値型の値にもなれる．
どの型になるかは，使われ方から決まる(型推論)．

## 関数の呼び出し

関数は，関数名のあとに引数を空白で区切って並べて呼ぶ．
括弧やカンマは使わない．

```console
ghci> max 3 5
5
ghci> length [1200, 350, 800]
3
ghci> sum [1200, 350, 800]
2350
```

括弧は，式をまとめるためだけに使う．
関数の呼び出しは，どの演算子よりも先に結び付く．

```console
ghci> show (1 + 2)
"3"
ghci> length [1, 2] + 1
3
```

`show 1 + 2`と書くと`(show 1) + 2`と読まれ，文字列と数を足そうとして型エラーになる．

## 演算子

| 演算子 | 意味 | 例 |
|---|---|---|
| `+`，`-`，`*` | 足し算，引き算，掛け算 | `1200 + 350` |
| `div`，`mod` | 整数の割り算の商と余り | ``10 `div` 3``は`3` |
| `==`，`/=` | 等しい，等しくない | `1 /= 2`は`True` |
| `<`，`<=`，`>`，`>=` | 大小の比較 | `3 < 5` |
| `++` | リスト(文字列)の連結 | `"1200" ++ "円"`は`"1200円"` |

`div`のような2引数の関数は，バッククォートで囲むと演算子のように2つの引数のあいだに書ける．
``10 `div` 3``は`div 10 3`と同じ意味である．

## 関数の定義

関数は，型シグネチャと定義の2行で書く．

```haskell
formatYen :: Int -> String
formatYen amount = show amount ++ "円"
```

- 1行目の型シグネチャは「`formatYen`は`Int`を受け取って`String`を返す関数である」という意味である．
- 2行目の定義は「`formatYen amount`は`show amount ++ "円"`に等しい」という意味である．`amount`が引数の名前で，`=`の右辺が戻り値である．`return`は書かない．

引数が2つある関数は，型シグネチャで`->`を2つ並べる．最後の型が戻り値の型である．

```haskell
addTax :: Int -> Int -> Int
addTax rate amount = amount + amount * rate `div` 100
```

```console
ghci> addTax 10 1200
1320
```

Haskellの関数は，同じ引数に対していつも同じ値を返す．
変数に値を入れ直す(再代入する)こともできない．
`amount`は「呼び出されたときに渡された値につけた名前」であり，定義の中で変わることはない．

関数名と変数名は小文字で始める．
型の名前(`Int`，`String`など)とモジュールの名前は大文字で始める．

## 文字列と数の変換

`show`は値を文字列にする．`read`は文字列を読んで値にする．

```console
ghci> show 1200
"1200"
ghci> read "1200" :: Int
1200
ghci> read "1200" + 1
1201
```

`read`がどの型の値を作るかは，使われ方から決まる．
2つ目の例では`:: Int`で型を指定している．
3つ目の例では`+ 1`と足しているので，数として読まれる．
数として読めない文字列を`read`に渡すと，プログラムはその場でエラーになって止まる．

```console
ghci> read "abc" :: Int
*** Exception: Prelude.read: no parse
```

誤った入力をエラーで止めずに扱う方法は，Iteration 4で学ぶ．

## リスト

リストは，同じ型の値を並べたものである．
`[]`は空のリストである．

```console
ghci> sum [1200, 350, 800]
2350
ghci> sum []
0
ghci> length ["1200", "350"]
2
ghci> map show [1200, 350]
["1200","350"]
ghci> map read ["1200", "350"] :: [Int]
[1200,350]
```

`map f xs`は，リスト`xs`の各要素に関数`f`を適用したリストを返す．
`map`のように関数を引数に取る関数については，Iteration 3で詳しく学ぶ．

## `$`

`f $ x`は`f x`と同じ意味である．
`$`はどの演算子よりも後に結び付くので，右側全体をまとめる括弧の代わりに使える．

```haskell
show $ 1 + 2      -- show (1 + 2) と同じ
```

hspecのテストでは，`describe "total" $ do ...`のように，`$`のあとに続く複数行をまとめて渡すために使う．

## コメント

`--`から行末まではコメントである．
`-- |`で始まるコメントは，すぐ下の定義を説明するドキュメントコメントになる(HLSがホバー表示に使う)．

## モジュール

1つのファイルが1つのモジュールになる．
ファイルの先頭で，モジュール名と，外に公開する名前(エクスポートリスト)を宣言する．

```haskell
module Kakeibo.Money
  ( total,
    formatYen,
  )
where
```

モジュール名はファイルの場所と対応させる．
`Kakeibo.Money`は，ソースディレクトリ(`src`)の下の`Kakeibo/Money.hs`に置く．

ほかのモジュールの関数は，`import`で使えるようにする．

```haskell
import Kakeibo.Money (formatYen, total)   -- 括弧の中の名前だけを使う
import Test.Hspec                          -- 公開されている名前をすべて使う
```

`sum`，`map`，`show`などは`Prelude`というモジュールの関数で，`import`しなくても使える．

## `error`

`error "メッセージ"`は，評価されるとメッセージを表示してプログラムを止める．
型シグネチャが決まっていて実装がまだない関数の仮の中身として使える．
演習用パッケージの`error "TODO: …"`がそれである．

```haskell
total :: [Int] -> Int
total _ = error "TODO: 金額のリストの合計を返す"
```

引数の名前の代わりに書いた`_`は「この引数は使わない」という意味である．

## `main`と`IO`

実行ファイルは，`Main`モジュールの`main`から始まる．

```haskell
main :: IO ()
main = do
  args <- getArgs
  putStr (unlines (run args))
```

- `IO ()`は「実行すると入出力をする処理(アクション)」の型である．
- `do`の中には，アクションを上から順に実行する手順を書く．
- `args <- getArgs`は，`getArgs`(コマンドライン引数を読むアクション)を実行し，結果の`[String]`に`args`という名前を付ける．
- `unlines`は，文字列のリストを，各要素の後ろに改行を付けて1つの文字列にする．`putStr`はそれを表示する．

`run`のような計算は`IO`の外の関数として書き，`main`は引数を読んで結果を表示するだけにする．
こうしておくと，計算の部分をテストから直接呼んで確かめられる．
`IO`と`do`の詳しい仕組みはIteration 6で学ぶ．

## hspec

hspecはテストを書くためのライブラリである．
テストは`Spec`型の値として書く．

```haskell
module Kakeibo.MoneySpec (spec) where

import Kakeibo.Money (total)
import Test.Hspec

spec :: Spec
spec = do
  describe "total" $ do
    it "空のリストなら0を返す" $
      total [] `shouldBe` 0
    it "複数の金額を足し合わせる" $
      total [1200, 350] `shouldBe` 1550
```

- `describe "名前" $ do …`：テストをまとめる見出し．ふつうは関数名を書く．
- `it "説明" $ …`：テストケース1つ．説明には確かめる振る舞いを書く．
- ``実際の値 `shouldBe` 期待する値``：2つの値が等しいことを確かめる．等しくなければテストは失敗し，両方の値が表示される．
- `do`の中に`describe`や`it`を並べると，複数のテストを1つの`Spec`にまとめられる．

テストスイートの`Spec.hs`には次の1行だけが書いてある．

```haskell
{-# OPTIONS_GHC -F -pgmF hspec-discover #-}
```

これは，コンパイルの前に`hspec-discover`というプログラムでこのファイルを作り直す指示である．
`hspec-discover`は，同じディレクトリ以下にある`〜Spec.hs`というファイルを探し，そのモジュールの`spec`をすべて実行する`main`を作る．
そのため，Specファイルは`spec :: Spec`を公開し，ファイル名を`〜Spec.hs`にする．
